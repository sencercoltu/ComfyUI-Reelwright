# Reelwright — feature specification

Reelwright is a single ComfyUI node with a built-in timeline editor. You use it to make
videos of any length with MiniMax H3 ref2va. It splits a project into scenes,
renders them with the native H3 nodes, and keeps every finished scene on
disk. Changing one scene re-renders only what depends on it. **Merge scenes**
joins the finished scenes into one film.

Status markers: ✅ implemented in v0.1 · 🧪 implemented, needs real-model
validation · 🗺️ roadmap.

## 1. Node

| | |
|---|---|
| ✅ Node id | `Reelwright` (category `video/Reelwright`) |
| ✅ Optional inputs | `model`, `clip`, `vae`, `audio_vae`. A wired input replaces the matching Global-tab loader for the whole run. |
| ✅ Outputs | `video` (the merged cut, or the last rendered scene; v0.6.0: the newest full cut, never a draft or range merge), `last_frame`, `audio`, `scene_plan` (JSON) |
| ✅ Without H3 (v0.6.0) | Reelwright also loads in a ComfyUI without the native MiniMax H3 nodes. Global → About says why they are missing, and a render is refused with that reason. |
| ✅ Editor | Timeline · Scene · Assets · Cast · Render · Global tabs inside the node |
| ✅ Pickers | Every drop-down is a type-to-filter combobox (every typed word must match); language and LLM model also accept values that are not in the list |
| ✅ Help | Every control has a hover tooltip; every section has a **?** button with a longer explanation that opens beside the icon, stays inside the node and can be dragged by its header |
| ✅ Storage | Settings are saved in the workflow, plus an autosave with versions on disk. Renders live under `output/reelwright/<project>/` |

The node does not output a frame batch for the whole film. A 90 s film at
1344×768 would need about 27 GB of RAM. The scene files on disk are the
output, and `video` points at them.

## 2. Global settings (Global tab)

- ✅ Project name, output folder name. Folder names drop accents ("Ömer" → `omer`), are at most 64 characters, and are `untitled` when no Latin letter is left (v0.6.0).
- ✅ **Project export and import** (v0.10.0, Project card): Export downloads the project as `<folder>.reelwright.json`; Copy JSON puts it on the clipboard. Import reads a .json file or pasted JSON (a project, or `{project: …}` such as a saved version), shows what it holds and asks first, then replaces the project in this node as one undo step. When the folders differ you keep this node's folder (and its `project_id`) or use the imported one. Pictures, sounds and renders stay files in ComfyUI's folders; the JSON names them only.
- ✅ One folder per project (v0.6.0). Each new node saves into its own folder, `untitled-xxxx`; the first rename moves it to the name's folder while it has no renders. A node pasted or duplicated from another becomes a separate project (new folder `<name>-2`…, new scene ids, renders start fresh). When a project's folder holds another project, a dialog offers **Use a separate project** or **Take over this folder**; until then nothing is written to disk and the footer shows "Folder in use".
- ✅ Models: diffusion model (ref2va), text encoder (Qwen3-VL, `minimax` CLIP type), video VAE, audio VAE, latent upscaler (used by Hires). Weight dtype and CLIP device are selectable.
- ✅ Global LoRA stack: enable, strength, order. Applied to every scene first.
- ✅ Output: aspect presets (21:9, 16:9, 4:3, 1:1, 3:4, 9:16) using the native H3 canvas rule (768 short edge, 768×1344 area cap, multiples of 32), or a custom width × height. Reference image size can be set to `match` or `max`.
- ✅ Sampling: steps, sampler (default `res_multistep`), scheduler (`simple`), seed and seed mode (fixed / +1 per scene / random), optional H3 sigma shifts (video 12, audio 3). CFG is fixed at 1.0 because H3 is CFG-distilled. With +1 per scene, each scene keeps its own seed number from when it was made, so adding, removing or moving scenes changes no other scene's seed (v0.6.0; existing scenes keep the seeds they had).
- ✅ Draft mode: lower resolution, fewer steps and an optional turbo LoRA, with the same seeds. Use it for fast previews, then render Final.
- ✅ **Hires** (v0.19.0, Hires card). Off by default. On: every pass is sampled at Output, then H3's latent upscaler (`MiniMaxH3LatentUpscaleWithModel` with the model chosen under Models) enlarges the video latent to Output × scale (1.25, 1.5, 1.75 or 2; up to 4 in the JSON) on the 32-pixel grid; the sound latent passes through. Every scene and the merged film end at that one size (`hires_size`, `project_output_size`); a scene of its own shape is fitted into it and letterboxed by the merge. **Refine steps** (0 = off) samples the big latent again for that many steps from **Refine denoise** of the noise (the last steps+1 sigmas of a schedule of steps / denoise steps), with its guides encoded again at the big size (a latent hand-off falls back to the frames); the first sampling's sound is kept. Scenes override **Hires: Off** (the merge enlarges that scene), refine steps and refine denoise (Scene → Generation). Drafts skip it unless Draft → **Upscale drafts** is on, and are never refined. The settings get `hires` {model, width, height[, refine_steps, refine_denoise]} only while it runs, so turning Hires off keeps every cache key; takes keep the sampling size in `width` / `height` and add `out_width`, `out_height`, `hires`. Time estimates use takes with the same Hires first. Without an upscaler the issues list has an error and a render that uses Hires is refused before the GPU.
- ✅ New-scene defaults: duration, how a scene starts, overlap frames, dialogue language.
- ✅ Long-scene settings: longest pass, overlap, crossfade, seam mode, how far a seam may move to land on a cut. v0.8.0: **Pass seams**: guide VAE, carry sound, `<Video 1>` at seams, hand-off and pass cache (§5).
- ✅ Memory policy and the "encode all prompts first" switch (see §8).
- ✅ LLM settings: OpenAI-compatible base URL, model, temperature, max tokens and presets. The API key is stored in the ComfyUI user folder, never in the workflow.
- ✅ Profiles: save the whole Global tab under a name and apply it to any project; update, delete and mark one as the default for new nodes. Stored in `user/reelwright/profiles.json` (never the API key) and shared by every Reelwright node on the server. A new node starts with the default profile and shows a banner to pick another. A profile saved before v0.5.0 brings its score in as a soundtrack track, with a note (v0.6.0).
- ✅ Override matrix: shows which scenes override which global setting.
- ✅ Autosaved versions: list them (date, time, size), restore one, delete one or delete all. The project's latest autosave (`project.json`) is never deleted. Restore first shows what the version changes: scenes brought back or removed, titles, lengths, starts, prompt text, shots, dialogue, references, cast, Global settings (v0.6.0), each scene's In the cut settings (v0.7.0). A damaged `project.json` falls back to the newest readable version.

## 3. Scenes (Timeline + Scene tabs)

- ✅ Unlimited scenes. Add, duplicate, delete, reorder, split at the playhead. Deleting asks for confirmation; deleting the only scene resets it to an empty scene. Split keeps the film's length (v0.6.0; the second half was one frame short), and split, duplicate and paste give the new scene its own seed.
- ✅ Right-click a scene (timeline or Scene tab strip) or an asset for its own menu; ComfyUI's node menu does not open inside the editor.
- ✅ **Drag to reorder** (v0.13.1): a sideways drag on a scene block moves the scene in the order. The block follows the pointer; a marker with a label ("→ 2 of 8 · after 02 …") shows where it lands: before the first other scene whose middle is right of the pointer. The release moves it (`actions.moveSceneTo`, one undo step, *Move scene*); Esc cancels; the lanes scroll near their edges. A drag that starts mostly up or down pans, as does Alt + drag. The first scene starts fresh (as with Move left / right).
- ✅ **What a duplicate keeps** (v0.13.1): Duplicate copies everything. A toast names what the copy keeps that decides what H3 gets besides its sections (shots and spoken lines with auto shots + dialogue, pass texts, hand-edited pass prompts, a Raw prompt), so the copy is not mistaken for a blank variant.
- ✅ Duration: drag the right edge of a scene on the timeline, or type it. Any length from 1 frame to 600 s (see §5).
- ✅ **Auto-roll** (v0.6.0): while a soundtrack sets the timing (§3a), changing a scene's length on the timeline or in the Scene tab takes the time from the next scene, so later scenes and their passes stay on the song. On by default; the **Auto-roll** toolbar toggle turns it off (then Ripple / Roll apply as before).
- ✅ How a scene starts:
  - **Fresh start**: hard cut, nothing carried over.
  - **Last frame**: the previous scene's final frame becomes guide frame 0 (fully preserved).
  - **Tail clip**: the previous scene's last N frames (17k+5) become a guide clip at frame 0, plus its audio. The overlap is trimmed in the final cut, so motion, light and sound continue.
  - The timeline is the cut (v0.5.0): a continuing scene starts inside the one before, over the frames it repeats (the tail clip, or the one last frame), where the merge puts it.
  - One rule everywhere (v0.6.0: planning, prompts, trimming, the timeline and the merge). A tail start past the re-anchor limit (§7) is a last-frame start. The tail overlap is at most 124 frames and never longer than the scene before or the scene itself; when fewer than 5 frames would be left, the scene continues from the last frame. The Scene tab's start card says when this happens.
  - Each scene's **visible start** (v0.6.0) is where it first shows new content: its start plus the frames it repeats. Next, Previous and Loop jump to it, and the Scene tab's "In" shows it.
  - **Named continuation** (v0.7.0, on by default, see §7): the frame or clip a continuing scene starts from is also sent to H3 as reference 1 and named in the prompt: the last frame as `<Picture 1>`, the tail clip of the scene before as `<Video 1>` (with its sound when an audio slot is free). It is still anchored as above.
- ✅ **In the cut** (v0.7.0): a Scene tab card, under Starts from, that sets how the merge puts the scene into the film (§9). It changes only the merge, never the render.
  - **Join**: transition (Cut, Crossfade, Dip to colour, Dissolve, Wipe, Slide, Circle open, Pixelize, Radial, Zoom in), direction for wipe and slide (← → ↑ ↓), length in frames (seconds shown beside it), dip colour, and the audio fade (labelled *Audio crossfade* when the transition overlaps; the merge uses it at plain cuts and in a dip a soundtrack makes, and crossfades the sound over the whole of an overlapping transition). A continuing scene shows "Joins by its continuation" (the tail overlap is crossfaded over Global → Long scenes → Crossfade, or the repeated last frame is dropped) and its transition can't be picked; the first scene has no join. With a soundtrack setting the timing, the card says the transition plays as a dip through its colour (with a swatch) inside both scenes, and shows the Dip colour field for every transition type.
  - **Start** / **End**: fade in from / fade out to a colour (frames + colour picker), audio fade in / out.
  - **Sound**: level in dB (−60 to +12) and **Mute**.
  - **Colour**: match **Off**, **Previous** or **A scene** (with a reference scene), then brightness, contrast and saturation sliders.
  - Warnings in the card: a fade-in on a continuing scene; a fade-out when the next scene continues from this one.
  - **Apply to all…** copies the card to all other scenes or to the scenes after this one (one undo step, "Cut settings → all scenes" / "→ later scenes"); a copy that would match a scene to itself has its colour match off. **Reset** puts the card back to a new scene's values; each field has its own reset. Every edit has its own History name.
- ✅ References: any asset, with a role (reference / first frame / last frame / keyframe at time t), a retention label, the features to keep, and whether to use a video's soundtrack.
- ✅ **Pose references** (v0.12.0; role `pose`, with `ref.cast` = a character and `ref.time`): a picture whose body pose that character takes, in the shot at time t. It goes to the pass whose span holds t (`model.pose_in_pass`; a time at or past the end counts for the last pass), after the cast's pictures, and takes a picture slot there (reference budget and "auto" packing count it). It is never a subject: the character's subject line cites it ("<Subject 1> is Mara, …, whose pose in [Shot 2] comes from <Picture 3>", ref-en.txt 2.1) and its retention line is "<Picture 3> (pose of <Subject 1> in [Shot 2]): attribute_transfer - the body pose is transferred to <Subject 1>; the person, clothing and setting in <Picture 3> do not appear" (ref-en.txt 4.1). Not sent, with a warning in Issues and on the reference, when it is not a picture, names no character, or its character is not in the scene (cast list or speaking; parts do not count). The LLM sees it as "pose for @Mara: only the body pose is used, the person in it does not appear". `model.pose_refs` / `model.js poseRefs`.
- ✅ **Clips of video and audio references** (v0.14.0; `ref.in` / `ref.out` in seconds on whole frames, `out` null = the file's end): each video or audio reference sends the part of its file between From and To (`model.ref_clip` / `refClip`: end capped at the file's length; seconds = end − start). The same asset can be added more than once; every video reference is a `<Video k>` of its own (each clip of a motion or style video a subject of its own, the same clip twice one subject shown in both), with or without its own sound (**With sound**, `ref.soundtrack`); an audio reference that repeats a clip already sent (same asset and range, or the whole file of a cast voice sample) shares its label. In text, `@V1` is the first reference of V1 in the scene and `@V1.2`, `@V1.3` … the next ones (`model.ref_tokens`; the tag map has them, the rewriter sees each clip as "@V1.2 walk (video, reference, the part from 00:10.000 to 00:14.500 of the file, with its own sound)"); a number the scene does not have is written in words with a warning. A trimmed clip carries `in` / `out` / `seconds` in the build and its range in the cache key; untrimmed references keep their builds and keys. The renderer decodes only the clip (`media.load_video(start=)`, `media.load_audio(start=)`), at most 15 s. Budgets count clip lengths (2-15 s per reference, 15 s in all per pass). Issues: an error when a clip starts after the file ends or ends before it starts; info when To is past the end. Scene → References: the clip's tag (click to copy), From / To / Length (seconds, `108f` frames, or `0:04.5` times), a bar of the whole file with draggable ends, **Whole file**, and **Preview** (a player kept across renders: From here, To here, Play clip). Timeline lanes and the inspector show each clip with its tag and range.
- ✅ Guides per pass (v0.6.0): a first-frame, last-frame or keyframe picture named in the text is sent only to the pass it guides; other passes name it in words. A guide video named in the text is also sent as a reference video, described by its place ("the opening clip of [Shot 1]"). A video guide always fits its pass: a last-frame clip ends on the guided frame, others are shortened to the room left; the Issues list says how much of it is used and how to keep all of it.
- ✅ Retention labels follow the H3 guide. Visual: `fully_preserved`, `partially_preserved`, `attribute_transfer`, `weak_reference`. Audio: `fully_copy`, `partially_copy`, `reference`, `weak_reference`.
- ✅ Shots: list of shots with start time, camera and action. Shot ticks show inside the scene block on the timeline and can be dragged. They are written as `[Shot 1] A wide shot: …`, `[Shot 2] At 00:05.000, the shot cuts to …`, as in MiniMax's Ref2VA guide. A shot cut can't be dragged into the trimmed start of a continuing scene (v0.6.0).
  - Rows (v0.8.0, Shots card and each pass tab): a text field that grows with the text (with @tag autocomplete), and the shot's start, end and length in scene time. Typing a length moves the next shot's start (between this shot + 1 frame and the shot after next − 1 frame); the last shot's length sets the scene's length by the timeline's Ripple / Roll / Auto-roll rule. A pass seam inside a shot (an overlap seam) shows as a chip ("seam 00:25.000").
- ✅ **On the beat** (v0.6.0, Shots card, when a soundtrack track is not muted): proposes shot start times on the soundtrack's beats (a bar start when it is about as near), at least half a beat apart and never in the repeated start; **Apply** moves them in one undo step.
- ✅ Dialogue lines: speaker (from the Cast), time, language, delivery and text. Written as `<Subject n> (S1) whispers, <d>[English] …</d>`. Speaker IDs follow speaking order inside each clip (first voice S1, next new voice S2), as the guide asks. The language is picked from H3's 11 stable languages or typed freely.
  - Length (v0.8.0): a line may have its own length in seconds (`duration`, > 0, at most 600). Empty, it is estimated: the words at 2.5 a second, a Chinese, Japanese or Korean character counting as a quarter word, at least 1 s (shown as the placeholder). Each row shows start, end and length in scene time, and warns when the line runs past a pass seam (it is cut off there) or past the scene's end. The merge's `.srt` uses the line's own length (§9).
- ✅ Camera: per-shot camera wording from presets, or a reference clip (uses a video slot).
  - v0.8.0: the picker lists the 20 camera moves of MiniMax's H3 guide (§11), then the project's own presets, and takes free text. Each shot can set the move's **amplitude** (Small / Medium / Large) and **speed** (Slow / Normal / Fast; Medium and Normal write nothing; greyed out without a move and for Static Shot, POV and the two shakes) and a **framing** (extreme wide, wide, medium wide, medium, medium close-up, close-up, extreme close-up, over-the-shoulder, two-shot, insert, low angle, high angle, overhead, Dutch angle).
  - A shot with a framing, amplitude or speed is written in the guide's form, the move as one sentence: `[Shot 1] A close-up: The camera pushes in with small amplitude at slow speed. …`, `[Shot 2] At 00:05.000, the shot cuts to a low-angle shot: The camera pans left with large amplitude. …`. A shot without them is written as before.
  - The timeline's Camera lane shows framing · move (the preset's name) · amplitude and speed.
- ✅ Prompt editor with two views:
  - **Structured**: six sections (subject definitions, summary, retention analysis, detailed description, soundscape, music). Each can be auto-filled from refs, cast, shots and dialogue.
  - **A tab per pass** (v0.8.0), in a scene of several passes: **Whole scene**, then **Pass k · 00:14.375–00:29.417** (scene times; a dot = the pass has text of its own; amber times = its text was written for another range). Whole scene: the summary is a *whole-scene note* (for you and the LLM, not sent) and the other sections are shared by every pass. A pass tab: range, length, frames and seam kind; its own six sections, where an empty one uses the shared or automatic text (shown as the placeholder; each section says *pass k only*, *shared* or *automatic*; **Use shared** clears it); its shots and dialogue as editable rows (numbered per pass, scene number beside them); **Write this pass** (§4). A hand-edited or Split pass prompt that replaces the pass is noted. When the passes move, each pass gets the text written for the time it overlaps most; **Use the new layout** stores them for the current passes (one undo step) and drops texts no pass gets. A single-pass scene that still has pass texts offers **Move into the sections** / **Drop them**.
  - **Where the text goes** (v0.13.1): on Whole scene each shared section says which passes use it (*shared by every pass*, *used by passes 2, 3 · pass 1 has its own*, or *not used · …*; a pass whose prompt is edited by hand uses no section); **Use in every pass** clears that section in the passes that have their own (one undo step). The detailed description shows the shot and spoken lines that go with it (*+ 2 shot lines, 1 spoken line from the scene*). A single-pass scene with a hand-edited prompt says so above its sections (**Use the sections** drops it), and What H3 receives shows that text in its editor.
  - The built prompt follows MiniMax's Ref2VA guide (`ref-en.txt`): the labels `subject_definitions:`, `summary:`, `retention_analysis:`, `detailed_description:`, `overall_soundscape:`, `non_diegetic_music:` each on their own line, in that order, with `N/A` for empty sections. Reference pictures that define a character, place, prop or style become `<Subject N>` lines (`<Subject 2> is the wooden pier at dusk, shown in <Picture 3>.`); standalone `<Picture N>` is kept for frame anchors. Retention lines name the shots a subject appears in (`<Subject 1> (appears in [Shot 1], [Shot 2]): fully_preserved - identity and appearance are retained.`).
  - Info lints point at the guide's advice: a short detailed description, an empty soundscape (N/A means silence), a reference asset without a description.
  - **Raw**.
  - In both views, refer to assets as `@P1`, `@V2`, `@A1`, to cast members as `@Mara` or `@{Old Keeper}`, and to the continuation clip as `@tail` (v0.7.0: in a pass that names the continuation, `@tail` is its `<Picture 1>` or `<Video 1>`). Each pass renumbers these into `<Picture k>`, `<Video k>`, `<Audio k>`, `<Subject n>`, in the order the native node presents references.
  - Tag syntax (v0.6.0): a name may have accents, digits, `_`, and single `'`, `’`, `-` or `.` inside it (`@Ömer`, `@O'Brien`; "@Anna." is `@Anna`). `@Mara's` is Mara's subject plus "'s". An `@` right after a letter or digit starts no tag, so e-mail addresses are text; `@@` writes a literal `@`. The same rule highlights, autocompletes and builds.
  - Unknown tags (v0.6.0): a name that looks like an asset code (`@P9`) or a code not attached to the scene is an error; any other unknown name is a warning and is written as plain text; a cast member who is not in the scene is written as the name, with a warning. `@soundtrack` / `@song` in a pass that gets no song is written as "the soundtrack" (info), never an error.
- ✅ Task tags are derived automatically: `reference generation`, `keyframe completion`, `video continuation`, `audio reference`, `audio reuse`, `video editing`. A video guide is *video continuation* (v0.6.0; *keyframe completion* is kept for pictures). A pass edited by hand, a Split prompt and a raw prompt get the task tags exactly once, at the start of the summary (or of the text); tags written by hand are replaced by the pass's own. v0.7.0: the continuation reference (§7) adds *keyframe completion* (a picture) or *video continuation* (a clip, plus *audio reference* when its sound is sent), never *reference generation*.
- ✅ Prompt preview shows exactly what each pass will send. v0.8.0: picking a pass tab opens that pass. v0.9.0: it follows the Prompt card's tabs (Whole scene shows every pass in turn, a pass tab that pass); it has no tabs of its own. v0.19.1: on Whole scene the passes sit in one panel that scrolls (at most 560 px tall).
- ✅ Per-scene overrides of any global setting: quality (draft or final), seed, steps, sampler, resolution, video VAE, audio VAE, diffusion model, LoRA stack (add to or replace Global, per-LoRA strength override). A hollow dot means the setting follows Global; a coral dot means it is overridden. "Reset to Global" clears them.
- ✅ Scene notes, timeline markers, lock (keep the current take even when what it continues from changes).
- ✅ Delete (v0.6.0): on the Timeline tab, Delete or Backspace removes the selected marker or soundtrack track without asking (Ctrl+Z brings it back); otherwise it deletes the selected scene, which asks first. Clicking a scene closes the marker panel.
- ✅ **Timeline layout** (v0.9.0): three panels: the monitor with its transport (top left), the selected scene's inspector with its summary and what is on screen at the playhead (top right), the timeline (below). Bars between them resize them (double-click resets; sizes in `ui.tl_mon` and `ui.tl_top`). No asset bin.
- ✅ **Monitor full screen** (v0.13.0): the transport's full-screen button, a double-click on the monitor, or F. The monitor moves into a box in the editor's root (`.rw-mon-fs`) that re-renders never replace, so full screen survives progress events; its panel shows a placeholder. A bar shows play/pause, the time, the scene and exit; a click on the picture or Space plays/pauses, Esc leaves. `timeline.js enterFull / exitFull / toggleFull`.
- ✅ **A new take while the film plays** (v0.13.0): when the starred take of the scene that is playing changes (a render finished), the monitor loads it and goes on playing from the same moment instead of stopping on its first frame.
- ✅ **Monitor captions and volume** (v0.9.0): the spoken line at the playhead is a caption, timed like the merge's .srt, updated on every frame while playing; CC turns captions off. A mute button and volume slider change only what the monitor plays (`ui.captions`, `ui.mon_volume`, `ui.mon_muted`).
- ✅ **Pass names** (v0.19.0): a pass tab's head has a name field; `scene.pass_names` {"<pass number>": name} (spaces collapsed, at most 60 characters, empty = no name; both models' `pass_names` / `passNames`). Everywhere a pass is listed it reads "Pass 2 · Harbour", the number always first (`passLabel`: prompt tabs, What H3 receives, Reset, Write prompts, rewriter, reference budget, timeline inspector, Render tab retakes). A name belongs to the pass number, so it stays when the layout moves; splitting a scene leaves the second part's passes unnamed. Names are for the editor only: no prompt, LLM request or cache key reads them.
- ✅ **Scene tab lists** (v0.9.0): a pass tab hides the scene's Shots and Dialogue cards. Shot and dialogue lists scroll inside boxes whose height a grip sets (`ui.shots_h`, `ui.lines_h`, shared by all scenes).
- ✅ **Write prompts replaces the shots** (v0.14.4): in a one-pass scene the written [Shot N] lines replace the shots in order whatever their count (extra written shots join at their written start, unwritten shots keep their text; `writeShots`); in a scene of several passes each shot that starts in a pass takes that pass's line (one line per shot), while a continuing shot's line stays in its pass (`takePassShots`). Only with auto shots + dialogue on.
- ✅ **Drag to reorder, Reset scene, LLM output, brief, preview frame** (v0.15.0): references, scene cast, scene LoRA items and the Global LoRA stack reorder by dragging a grip (`ui.sortable` / `dragGrip`; ↑/↓ on the grip; one undo step). Prompt card: **Reset scene** clears the six sections, `prompt.passes` and `prompt.pass_prompts` (confirm; one undo step). LLM progress events carry `think_add`/`text_add` deltas at offsets; the editor keeps them per job and request (`llmjob.feedStream`) and shows them in a popup over the editor (Output button on LLM progress rows; follows a batch). `scene.prompt.brief`: the author's Write prompts text, sent in `pass_request` / `rewrite`, never written by the LLM; the first single-pass Write prompts copies an author's summary into an empty brief. A written camera move is always set as the preset. The latent preview shows the middle latent frame of the pass's new part (`render.preview_frame`).
- ✅ **Dialogs next to their trigger** (v0.15.1): `choiceDialog` / `confirmDialog` place the box below the pressed control (above it near the window bottom), next to the focused control after a key press, else at the pressed point; with no recent trigger, in the middle of the visible part of the node. Always inside the visible part of the root (`ui.placeNear`).
- ✅ **Sheets named, small sheets flagged, video anchors** (v0.16.0): a packed sheet reads "shown in <Picture k>, a sheet of N views of the same person|place|object". Lint warns when a sheet picture reaches H3 under 300 px (`model.tile_pixels` at the scene's render size and Reference images). `cast.video_anchors` [{id, asset, in, out, soundtrack}]: sent with the cast member's subject ("and in <Video k>") in every pass it is in, after everything else, within 3 videos / 15 s of video / 12 files (a clip shortened to the seconds left when ≥ 2 s); its sound only when asked and an audio slot is free (`model.pick_video_anchors`, the budget the same).

- ✅ **Longer scenes** are split into several passes, each no longer than the longest-pass setting.   - Shots, dialogue and keyframes are assigned to the pass that contains them, with timestamps re-based to that pass. Ones before 0 s or in the last half frame of the scene are moved inside it, so they land in exactly one pass (v0.6.0). Ones that start at or after the scene's end belong to no pass: the issues list reports them as errors (lengthen the scene or move them), and the scene is not rendered until then.
  - Written `[Shot N]` lines (v0.6.0) go only to the pass that holds that shot, renumbered for the pass, with their MM:SS times moved to pass time. A pass's first shot says it continues when the shot carries on across an overlap seam. Without shots on the timeline the lines go to every pass (with a warning).
  - Cast anchors are re-sent to every pass. A cast member's voice sample goes only to the passes where they speak (v0.6.0).
  - Each pass seed is the scene seed plus the pass index.
  - Each pass is saved on its own in the scene's **pass cache** (v0.6.0), so a failed or stopped render starts again where it stopped. **Pass retake** (§8) gives one pass a new seed and keeps the others.

  - Lint (v0.8.0): a warning per scene listing the passes without a summary of their own; an info when pass texts were written for another pass layout; a tip for a scene with overlap seams and no shot cuts (each seam re-encodes the end of the pass before, so later passes can drift; add shot cuts near the seams).
- 🧪 **Pass seams** (v0.8.0, Global → New scenes and long scenes → Pass seams).   - **Guide VAE** (default: the video VAE): encodes every reference picture and clip, the continuation reference and every guide of every pass; the video VAE still decodes. ## 11. MiniMax H3 facts used

- Frame grid 17k+5 at 24 fps; trained range 124–362 frames. Audio 32 kHz stereo (40 latent frames/s).
- Canvas: 768 short edge, area cap 768×1344, multiples of 32.
- References: up to 9 images, 3 videos (2–15 s), 3 audio clips. Prompt numbering follows the native node: images first, then videos (each video's soundtrack takes an `<Audio j>` number right before its `<Video k>`), then standalone audio.
- `MiniMaxH3AddGuide` anchors images, clips (17k+5 frames) and audio at any frame; negative indices count from the end.
- A first-frame picture or a video the target continues is also a reference with a name (ref-en.txt 2.2, 2.3, 3, 5.3): a subject_definitions line, a `fully_preserved` retention line and a mention in [Shot 1]; it is *keyframe completion* or *video continuation*, not *reference generation* (used by Name the continuation, v0.7.0).
- CFG-distilled: CFG 1.0. Native blueprint: `res_multistep` sampler, `simple` scheduler, 20 steps.
- Camera moves (base-en.txt 4.3, used by the camera picker, v0.8.0): Zoom In / Out, Push In, Pull Out, Pan Left / Right, Truck Left / Right, Tilt Up / Down, Pedestal Up / Down, Arc Shot, Tracking Shot, Static Shot, Shake Slightly / Strongly, POV, Roll Clockwise / Counterclockwise; each with an amplitude (small / large) and a speed (slow / fast), written as one sentence ("The camera pushes in with small amplitude at slow speed.").
- Video VAE (v0.8.0): it keeps no state between calls. The encoder takes 17-frame chunks one at a time (a causal 3D CNN); a chunk gives 5 latents (1 frame, then 4 each), and the last 3 latents of a clip are dropped, so 17k+5 frames give 5k+2 latents. An overlap of 17j+5 frames at the end of a 17m+5-frame pass starts on a chunk boundary, so its latents are the pass's last 5j+2 (what the latent hand-off uses). ComfyUI also loads LightVAE Lite encoders, which prune resnet blocks down to their shortcut; every variant shares the same 24-channel normalised latent space. The sampled video latent is in the space `vae.encode` returns.
